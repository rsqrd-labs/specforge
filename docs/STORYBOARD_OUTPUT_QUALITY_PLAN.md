# Storyboard Output Quality — Remediation Plan

> **Problem report (owner, 2026-07-04):** decks generated by the Storyboard
> feature have (1) slides whose content is visually cut off, (2) generally
> shallow/generic content, (3) architecture diagrams that are wrong for the
> product, and (4) `SPEC`/`PLAN`/`HARNESS`/`TASKS` citations displayed on the
> slides themselves. The feature may *use* the sources internally, but a launch
> keynote must never read like an audit trail.
>
> **This document is the complete work order.** Every root cause below is
> traced to a specific mechanism in the code; every fix names the files, the
> contract changes, the back-compat rules, and the tests. A coding agent should
> be able to execute each phase from this document alone.
>
> **Relationship to `docs/STORYBOARD_KEYNOTE_REDESIGN_PLAN.md`:** that plan
> (issue #17) built the current fixed topology graph and per-type slide
> layouts. Its §7.3 explicitly deferred "LLM-driven edges / product-specific
> topology" until "real decks show the canonical topology is too generic for
> specific products". That condition has now been observed. This plan is the
> anticipated follow-up; where the two disagree, **this document wins**.

## 0. TL;DR — complaint → root cause → fix

| # | Complaint | Root cause (verified in code) | Fix (phase) |
|---|-----------|-------------------------------|-------------|
| 1 | Slides cut off (live deck) | Fixed 16:9 stage with `overflow: hidden`; headline type up to 104–120px; no fit-to-frame behavior. Only the arch slide has scroll relief. | P1: smaller type scale, container-relative sizing, universal overflow safety net, optional stepped autofit |

Recommended execution order: **P1 → P2 → P3 → P4 (verification)**. P1 is pure
presentation (no schema/LLM change) and fixes what a viewer notices first.

## 1. Non-negotiable invariants (do not regress these)

1. **The LLM returns inert structured data only.** All markup/CSS/SVG/PDF is
   produced by trusted code that escapes every value. Never let any payload
   field reach the DOM/HTML unescaped, never honor a media promise, never
   introduce free-text → CSS/class-name paths. (See `RENDERING SAFETY` in
   `backend/prompts/storyboard.py` and the module docstring of
   `backend/services/pipeline/storyboard_renderer.py`.)
2. **Diagram geometry stays code-owned.** The LLM fills `label` / `summary` /
   `source_refs` per layer. It never describes coordinates or edges. P2 changes
   *which* planes render, never *who* computes geometry.
3. **The storyboard prompt lives in code, never Langfuse**
   (`backend/prompts/storyboard.py` module docstring).
4. **Credits/idempotency/refund flow is untouched.** Do not modify `_reserve`,
   `_fail_and_refund`, `recover_stuck_storyboards`, or transaction boundaries
   in `storyboard_service.py`.
5. **Every already-persisted Storyboard must keep rendering.** Renderers
   (live deck, public share, HTML/PDF export) must accept any historical
   payload shape: full 8-layer diagrams, 1 200-char excerpts, badge-era
   payloads. Rendering is defensive; validation strictness applies only to
   *fresh generations*.
6. **Pydantic stays equal-or-stricter than the harness JSON schema.** The
   documented rule is "any payload the Pydantic model accepts also satisfies
   `harness/schemas/storyboard-payload.schema.json`". When P2 *loosens* the
   Pydantic side (8 required layers → core subset), the JSON schema must be
   loosened **in the same commit** or the invariant breaks in the other
   direction (schema stricter than model).
7. **Grandfathering pattern.** Section regeneration re-validates the whole
   spliced payload with `context={GRANDFATHER_NOTE_DEPTH: True}`
   (`prompts/storyboard.py`, used by `_run_section_generation` in the service).
   **Every new fresh-generation floor added by this plan must be behind the
   same context flag** so regenerating one act of a pre-existing deck never
   fails on carried-over content. Reuse the existing key or add sibling keys in
   the same `info.context` dict.
8. **Privacy:** no generated payload content in logs. Failure reasons stay
   coarse, content-free labels (`payload_parse`, `payload_schema`, `provider`,
   `timeout`).

## 3. Root causes in detail (read before editing)

### 3.1 Live-deck clipping
`.storyboard-stage-frame` is `aspect-ratio: 16/9; min-height: 420px; overflow: hidden`
(`frontend/src/index.css` ≈ L12343–L12371). Inside it, `.storyboard-slide` is
`height: 100%`. Only `.storyboard-slide--arch` gets `overflow-y: auto`
(≈ L12655). Meanwhile the schema allows 18-word headlines (`_MAX_HEADLINE_WORDS`)
rendered at `clamp(36px, 5vw, 72px)` base, `clamp(44px, 6.6vw, 104px)` on
feature slides, `clamp(48px, 7.4vw, 120px)` on the cover — plus ≤ 45 words of
`visible_text`, up to 5 visual points, kicker chips, and the badge row. At the
caps, content overflows the frame bottom and is silently clipped. `vw` units
also mis-scale when the deck is not full-viewport-width (workspace page,
non-fullscreen).

### 3.2 PDF clipping
`backend/templates/storyboard.html.j2` uses fixed `.page { height: 210mm;
overflow: hidden }` (deliberate, to prevent slide-splitting across pages) with
generous mm type sizes. Same overflow-at-the-caps failure, in the artifact a
user hands to a judge.

### 3.3 Citations on presentation surfaces
- `StoryboardDeck.tsx` renders `storyboard-slide-source-badges` (the
  `slide.sources` enum values, e.g. `SPEC PLAN`) inside the slide content of
  **every** slide.
- `ArchitectureReveal.tsx` prints `layer.source_refs[0].source_id` (e.g.
  `PLAN:architecture`) inside each diagram node (`arch-node__source`).
- `storyboard.html.j2` renders the same chips on every printed page (two
  `page.sources` chip loops), fed by `sources` in
  `storyboard_renderer._build_deck_context`.

The correct home already exists: `SourceLayer.tsx` is a toggleable evidence
overlay (S key / "Sources" button) that filters `source_map` by the current
slide id, and `technical_appendix_md` carries written depth. The badges are
redundant noise on the audience surface.

### 3.4 Diagram wrongness
`REQUIRED_ARCHITECTURE_LAYERS` (`prompts/storyboard.py`) makes all eight kinds
mandatory — `StoryboardDiagram._architecture_reveal_layers` rejects any
`architecture_reveal` missing one, and the harness schema pins `minItems: 8`.
The prompt then instructs "layers cover every plane". Consequence: for any
product that is not a web-SaaS-with-LLM (CLI, batch pipeline, mobile app, no
third-party integrations), the model **must invent** an `llm` / `frontend` /
`integrations` layer to pass validation — in direct conflict with the prompt's
own "never invent components" rule. The topology constants
(`ArchitectureReveal.tsx` `NODE_CENTERS`/`EDGES`, mirrored in
`storyboard_renderer.py`) then draw the same six boxes + two overlays for every
product. The diagram is confidently wrong precisely when the product is
interesting.

### 3.5 Content quality
Three compounding mechanisms:

1. **Starved + skewed grounding.** `_render_sources_block` feeds only
   `source.excerpts`: at most 9 sections × ≤ 1 200 chars (~2.7K tokens). Five
   of nine specs are PLAN security/capacity/STRIDE/SLO/FMEA; product substance
   is `SPEC:overview` + `TASKS:must` ≈ 2 400 chars. There is **no**
   requirements, user-journey, or component-list excerpt. The full scrubbed
   artifacts already sit unused in `StoryboardSourcePackage.artifacts`.
2. **Output-side truncation pressure.** `_OUTPUT_TOKEN_BUDGET = 16384` is
   hardcoded in `storyboard_service.py` (not in `OUTPUT_TOKEN_BUDGETS`; no
   `resolve_output_budget`; no `stopped_by_limit` doubling repair — note
   core-gen budgets are 49 152 with 64K ceilings now). The user prompt demands
   *verbatim* ≤ 1 200-char excerpts, keyed per slide in `source_map`, plus 8
   diagram layers with their own excerpt copies, plus ~80–160-word notes per
   slide. A well-populated deck plausibly exceeds 16K output tokens →
   truncated JSON → parse failure → `build_repair_user_prompt` re-sends the
   *entire broken output* under the *same* cap (up to `_MAX_REPAIR_ROUNDS = 2`
   rounds), then a one-shot mid-tier escalation under the same cap again. Up
   to 6 doomed calls; and the decks that *do* survive are systematically the
   thinnest ones. Note: the verbatim demand is pure waste —
   `_validate_payload_against_source` deliberately verifies only
   `source_id` + enum binding, never excerpt text (see its docstring).
3. **No quality trigger.** Primary tier is cheap (Haiku 4.5 via
   `generation_tier_policy`); `_run_storyboard_completion` escalates only on
   `StoryboardPayloadError`. A schema-valid mediocre deck ships as-is. There
   is no slide-substance floor (`visible_text` has no minimum; a `product`
   slide with no `points`/`metric` renders as decorative color swatches via
   `SlideVisual`'s motif fallback), and no deck-shape guidance (an act can be
   one thin slide).

## 4. The fixes

### Phase 1 — Presentation surface (frontend + templates; zero contract change)

No schema, prompt, or service changes. Existing stored decks improve
immediately. `slide.sources` and `source_map` **stay in the payload** (they
feed SourceLayer and grounding validation); only rendering changes.

**P1.1 Remove citations from audience surfaces.**
- `StoryboardDeck.tsx`: delete the `storyboard-slide-source-badges` block from
  the slide `<article>`. Keep the "Sources" header button + SourceLayer
  overlay exactly as-is (that is the evidence surface, correctly
  permission-gated by `allow_source_layer`).
- `ArchitectureReveal.tsx`: remove the `arch-node__source` element (the
  `source_id` printed in each node). Layer evidence remains reachable via
  SourceLayer (diagram `source_refs` may also be surfaced there later — out of
  scope).
- `storyboard_renderer.py` + `storyboard.html.j2`: drop `sources` from
  `_build_deck_context` pages and remove both chip loops from the template.
  Also grep the template/renderer for any node-level source id emission in the
  offline topology (`_build_arch_topology`) and remove it.
- Dead CSS: remove the `.storyboard-slide-source-badges` rules.
  `.storyboard-source-preview` (which shares a selector with the badges) has
  no TSX usage as of this writing — grep and remove it too if that's still
  true.
- Tests to update: `StoryboardDeck.test.tsx` (badge assertions),
  `test_storyboard_renderer.py` (chip markup assertions),
  `ArchitectureReveal.test.tsx` if it asserts node source ids. Add inverse
  assertions: rendered slide/page HTML contains **no** `SPEC`/`PLAN` chip and
  no `source_id` string.

**P1.2 Fix live-deck clipping.** In `frontend/src/index.css`:
1. Make the stage a size container: `container-type: size` on
   `.storyboard-stage-frame`; convert storyboard type clamps from `vw` to
   `cqw` so type scales with the *stage*, not the viewport.
2. Reduce the scale: base slide `h2` → `clamp(28px, 4.6cqw, 56px)`; feature →
   `clamp(36px, 6cqw, 84px)`; cover → `clamp(40px, 6.8cqw, 96px)`; metric
   figure → `clamp(48px, 9cqw, 132px)`. Tune visually, but the cover must fit
   an 18-word headline at 1280×720 without clipping.
3. Universal safety net: give every layout what the arch slide already has —
   on `.storyboard-slide`: `min-height: 0; overflow-y: auto` (plus
   `min-height: 0` on the grid children). A scrollbar on a pathological slide
   is strictly better than silent truncation.
4. Optional polish (only after 1–3): a deterministic stepped autofit —
   `useLayoutEffect` + `ResizeObserver` on the slide article; while
   `scrollHeight > clientHeight` and step < 3, increment a `data-fit-step`
   attribute; CSS defines a reduced type scale per step. Unit-testable by
   mocking the two heights. Do **not** implement continuous transform-scaling
   (blurs text, breaks the glass styling).

**P1.3 Fix PDF clipping.** In `storyboard.html.j2` / `storyboard_renderer.py`:
- Reduce headline/body mm sizes ~15–20% and tighten line-heights until the
  max-cap fixture (below) fits every page variant.
- Server-side defensive clamps in `_build_deck_context`: headline hard-cap for
  render (e.g. 120 chars + ellipsis), `visible_text` cap (~360 chars is
  already schema-max; keep), points already capped at 5 — also cap each point
  to ~90 chars with ellipsis. Clamping strings for *rendering* does not touch
  stored payloads.
- Keep `overflow: hidden` on `.page` (it prevents page-splitting); the fix is
  making content fit, with clamps as the backstop.

**P1.4 Max-cap fixture.** Add to `testPayload.ts` (and a Python equivalent in
`test_storyboard_renderer.py`) a deck at the schema maxima: 18-word/140-char
headlines, 45-word `visible_text`, 5 points × 8 words, six acts, cover +
metric + arch slides. Use it in deck/renderer tests. This is the regression
anchor for every future layout change.

**P1 acceptance:** no `SPEC|PLAN|HARNESS|TASKS` text anywhere on slide surfaces
(live, public, HTML, PDF) while SourceLayer still shows per-slide evidence;
max-cap fixture renders un-clipped at 1280×720 and 1920×1080 and in PDF;
`pnpm tsc && pnpm test`, backend pytest, and existing visual behavior
(act accents, transitions, reduced-motion) all green.

### Phase 2 — Diagram truthfulness (schema v1.5, prompt, both renderers)

Goal: the diagram shows **only planes the product actually has**. Geometry
stays constant-driven; the model still never emits edges or coordinates.

**P2.1 Contract.** In `prompts/storyboard.py`:
- Split the eight kinds into `CORE_ARCHITECTURE_LAYERS = ("client", "api",
  "data")` (universal: an actor, compute, state) and
  `OPTIONAL_ARCHITECTURE_LAYERS = ("frontend", "llm", "integrations",
  "trust", "recovery")`. Keep the closed kind enum unchanged (all eight + `group`
  remain *valid*).
- `StoryboardDiagram._architecture_reveal_layers`: require core kinds present;
  optional kinds are allowed but no longer required.
- Bump `STORYBOARD_PROMPT_VERSION` → `"storyboard-v1.5"`.
- Prompt (`ARCHITECTURE REVEAL` block): replace "layers cover every plane"
  with: always include `client`, `api`, `data`; include each optional plane
  **only if the PLAN/SPEC actually describes such a component** ("omitting an
  absent plane is correct; fabricating one is a failure"); a summary must name
  the real components from the sources (e.g. "FastAPI + arq worker", not
  "API layer").
- Update `_MINIMAL_PAYLOAD_SHAPE` / `_CANONICAL_KEYS_BLOCK` text accordingly.
- Old stored decks (all 8 layers) still validate under v1.5 rules (8 ⊇ core),
  so section-regeneration splices keep working with no extra grandfathering.

**P2.2 Harness schema — same commit.** In
`harness/schemas/storyboard-payload.schema.json`,
`architecture_reveal_diagram`: `minItems: 8` → `3`; replace the single
`contains {kind: client}` with `allOf` of three `contains` (client, api,
data). Update `harness/tests/backend/test_phase23_storyboard_contract.py`
fixtures: add a minimal-subset diagram case (valid) and a missing-`api` case
(invalid). Keep invariant §1.6: Pydantic ⊆ JSON schema.

**P2.3 Live renderer.** `ArchitectureReveal.tsx`:
- Derive `present: Set<kind>` from `diagram.layers`. Old payloads → all 8;
  new payloads → subset.
- Render only present boxes. Delete the `layerForKind` placeholder text
  ("This layer was not described…") — absence now means *omit*, not
  apologize.
- Edges from present boxes only: `client → frontend → api` collapses to
  `client → api` when `frontend` absent; `api → sink` for each present sink of
  `{data, llm, integrations}`.
- Deterministic re-centering (keep it constant-table simple): sink column
  y-positions by present-sink-count — 1 → `[300]`, 2 → `[180, 420]`,
  3 → `[118, 300, 482]`. Chain x-positions by chain length — with `frontend`:
  `104 / 330 / 556` (today's values); without: `104 / 430` for
  `client / api`. `trust`/`recovery` regions render only if that kind is
  present, bounding only *present* members (skip the region if < 2 members).
- Caption and `currentStep` math switch from the fixed 8 to
  `ordered-present.length` (check `StoryboardDeck.tsx`'s
  `ARCHITECTURE_LAYER_SEQUENCE.length` usage).
- Node label overflow: the export already wraps labels at ~20 chars × 2 lines
  (`_wrap_label`); give live nodes an equivalent CSS clamp
  (`-webkit-line-clamp: 2`) so long labels can't spill the 168×88 box.

**P2.4 Offline renderer.** Mirror the same present-subset layout tables in
`storyboard_renderer.py` (`_build_arch_topology`, `_arch_node_box`,
`_arch_edge_path`, `_arch_region`). The file already documents that it mirrors
the TSX constants — keep both sides' numbers in sync and extend that comment
contract to the new variant tables.

**P2.5 Types + fixtures.** `frontend/src/types/storyboard.ts` needs no type
change (kinds unchanged); update `testPayload.ts` to include one subset-diagram
deck. Tests: `ArchitectureReveal.test.tsx` (subset renders N nodes, no
placeholder text, collapsed edge present; 8-layer legacy payload still renders
all 8), `test_storyboard_renderer.py` (same for SVG output),
`test_storyboard_prompt.py` (core-only diagram validates; missing `data`
fails; legacy 8-layer validates).

**P2 acceptance:** a payload with layers `{client, api, data}` renders a
3-box chain in live + PDF with no invented planes; legacy decks render
unchanged (all 8); harness contract tests green; prompt version v1.5.

### Phase 3 — Content quality (grounding, budget, shape, gate)

**P3.1 Rebalance and enrich grounding.** `storyboard_source.py`:
- Make the excerpt cap per-spec: add `max_chars: int = 1200` to
  `_SectionSpec`; `_bound` takes the cap as a parameter.
- Add product-substance specs (order matters — product first):
  - `SPEC:requirements` — include ("functional requirements", "requirements",
    "features", "capabilities"), 2 800 chars.
  - `SPEC:journeys` — include ("user journey", "user stories", "acceptance
    criteria", "personas", "user experience", "ux"), 2 000 chars.
  - `PLAN:components` — include ("components", "component breakdown",
    "modules", "services", "tech stack", "technology choices"),
    2 400 chars; exclude ("security").
- Raise `SPEC:overview` and `PLAN:architecture` to 2 400–2 800 chars. Keep the
  five security/ops specs at 1 200.
- Keep everything else (scrubbing, finalised-only, determinism, missing-section
  recording) untouched. New total prompt ≈ 20K chars ≈ 5K tokens — acceptable
  for a 25-credit generation; system prompt is provider-cached
  (`cache_system=True` already set).
- Tests: `test_storyboard_source.py` — new specs extracted, per-spec caps
  honored, missing sections still recorded.

**P3.2 Kill the verbatim-excerpt output tax (prompt-only; no schema change).**
`prompts/storyboard.py` user prompt: replace "Copy every source_map and
diagram source_refs excerpt verbatim … no paraphrasing, no ellipses" with:
"each excerpt is a **short** supporting quote or tight paraphrase of the named
source section, ≤ 300 characters". Schema caps stay at 1 200 (old decks and
generous models both stay valid — validation never checked verbatim-ness
anyway, per `_validate_payload_against_source`'s docstring). `SourceLayer.tsx`
needs no change (it already bounds display). This alone removes the single
largest output-token multiplier.

**P3.3 Real output budget + truncation repair.** 
- `output_budget.py`: add `"storyboard.generate": 32768` to
  `OUTPUT_TOKEN_BUDGETS` and `16384` to `_OUTPUT_BUDGET_FLOORS`.
- `storyboard_service.py`: delete `_OUTPUT_TOKEN_BUDGET`; resolve per attempt
  with `resolve_output_budget("storyboard.generate", provider=…, model=…)`
  (per-attempt matters: primary and escalation models have different
  ceilings).
- Truncation-aware retry in `_complete_and_validate` /
  `_parse_validate_and_ground`: when a **parse** failure's raw output does not
  end with `}` after `_extract_json_object` stripping (the truncation
  signature), retry once on the same model with `min(budget × 2,
  model_max_output_tokens(provider, model))` **before** consuming repair
  rounds (repairing a truncated body under the same cap is provably futile —
  the repair prompt re-sends the whole broken payload and asks for more).
  One doubling max, then the normal repair/escalation ladder proceeds.
- Wall clock: pass an explicit `timeout=540` to `complete_with_timeout` for
  storyboard (the default 360 s is tight for 32K tokens on a mid-tier model;
  this path is a background task — the HTTP request never waits, and the
  30-minute stuck-recovery sweep is unaffected).
- Optional observability: a `storyboard.truncation_retry` structured log line
  (content-free) or counter alongside the existing
  `record_storyboard_escalation` family in `services/observability`.
- Tests: `test_storyboard_service.py` — truncated-raw triggers exactly one
  doubled-budget retry then proceeds; budget resolves per model; timeout maps
  to `timeout` error type as today.

**P3.4 Deck-shape + substance contract.** 
- Prompt (`SLIDE RULES`): target **12–18 slides total, 2–3 per act** (Opening
  Thesis and Launch Close may be 1–2); every `product` / `walkthrough` /
  `trust` slide must carry a `points` array (3–5 entries) **or** a `metric`;
  headline and `visible_text` must not restate each other.
- Validator (fresh-only; grandfathered via §1.7 for splices): in
  `StoryboardSlide` or payload-level — `product`/`walkthrough`/`trust` slides
  require a non-empty `points`/`metric` descriptor. Do **not** hard-validate
  total slide counts (a count miss would burn repair rounds for marginal
  gain); leave pacing to the prompt + quality gate.
- Renderer note: with the substance floor in place, `SlideVisual`'s
  swatch-motif fallback becomes a legacy-deck-only path — keep it (invariant
  §1.5).

**P3.5 Deterministic quality gate → existing escalation.** New module
`backend/services/pipeline/storyboard_quality.py`, pure function
`assess_payload_quality(payload: StoryboardPayload) -> list[str]` (finding
strings, content-free-summarizable). Deterministic checks only — no LLM, no
I/O:
- headline ↔ `visible_text` near-duplication (normalized token overlap > ~0.7);
- per-act slide count outside 1–4, or total outside 8–24;
- interior acts (Product Vision / Walkthrough / Architecture / Trust) whose
  slides *all* lack `points`/`metric` descriptors;
- talk tracks that are near-copies of their slide's `visible_text` (same
  overlap test) — notes must add depth, not echo;
- fewer than 2 distinct `visual.kind`s across the deck (monotone template
  output).

Wire it into `_parse_validate_and_ground` after
`_validate_payload_against_source`: findings raise
`StoryboardPayloadError("schema", "quality: …")`, which (a) feeds the repair
prompt — the model gets one cheap chance to fix pacing/duplication — and (b)
on exhausted repairs triggers the **existing** one-shot mid-tier escalation in
`_run_storyboard_completion` and its `record_storyboard_escalation` metrics.
Zero new plumbing. Keep the checks *loose* (they gate junk, not style) and
unit-test each rule in isolation (`test_storyboard_quality.py`).

Escape hatch (optional, recommended): settings flag
`storyboard_force_mid_tier: bool = False`; when true,
`_resolve_storyboard_primary_route` requests `("mid", "strong")` regardless of
`generation_tier_policy`. One flag, no policy drift for other features
(`tier_policy.py` stays the product-wide source of truth). Flip it only if the
escalation-rate metrics show the cheap tier keeps failing the gate.

**P3 acceptance:** generation with the enriched sources succeeds end-to-end on
all three providers in dev; `thought2build_storyboard_escalations_total` and
failure-rate metrics do not regress; a synthetic truncated response consumes
one doubling retry, not three repair calls; fresh decks carry substance
descriptors on all interior product slides; section-regeneration of a
pre-v1.5 deck still validates (grandfather paths tested).
